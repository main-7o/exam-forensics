# exam-forensics

시험 응답 데이터로 **답안 공유, AI 부정행위, 문제 유출, 비정상 응답시간** 의심 신호를 찾는 오픈소스 통계 도구입니다.
Caveon Data Forensics 같은 상용 시험 보안 서비스가 쓰는 기법 계열(유사도, 이상응답, 사전유출, 응답시간, 성적변화, 공모 군집, 고사장 분석)을 구현하고, AI 시대에 맞는 탐지 기법을 더했습니다.

- **분석은 완전 오프라인:** 분석 코드에 네트워크 기능이 없습니다. 수험생 데이터가 기관 밖으로 나가지 않습니다.
- **AI 수집은 분리:** AI에게 시험 *문제*만 보내는 별도 명령(`collect-ai`)이 있습니다. 수험생 데이터는 이 명령에 들어가지 않습니다. 로컬 AI(Ollama)를 쓰면 이 단계까지 오프라인으로 할 수 있습니다.
- **의존성:** Python 3.9 이상, numpy. Anthropic(Claude)으로 수집할 때만 `anthropic` 패키지가 필요합니다.
- **속도:** 수험생 1만 명 × 45문항, 모든 분석을 노트북에서 약 6초 안에 끝냅니다. 고사실을 넘는 전국 단위 탐색(`--cross-room`)은 10만 명에 약 90초입니다.

> ⚠️ **이 도구의 결과는 부정행위의 증거가 아닙니다.** 통계 신호는 조사할 대상의 우선순위를 정하는 데만 쓰세요.
> 최종 판단은 반드시 현장 기록, 진술, 물증 같은 다른 근거와 함께 사람이 내려야 합니다.

## 탐지 방법

모든 p값은 귀무 모형(같은 점수대 수험생은 문항마다 독립적으로, 그 점수대의 실제 선택 비율대로 응답한다) 아래에서 **근사 없이 정확하게** 계산합니다. 연속 통계량은 0.02 간격으로 이산화한 뒤, 그 분포를 동적계획법으로 정확히 구합니다.

| 방법 | 잡는 것 | 원리 | Caveon 계열 대비 |
|---|---|---|---|
| **답안 공유** | 베끼기, 답 돌려보기 | ① 같은 오답 개수 정확 검정으로 모든 쌍을 훑고 ② 후보 쌍은 **"f 비율을 베꼈다" 대 "독립" 우도비**로 정밀 검정합니다. 드문 일치(어려운 문항의 정답, 인기 없는 오답)일수록 무겁게 셉니다 | M4처럼 정답 일치와 오답 일치를 함께 쓰되, 문항마다 일치의 희귀도를 가중합니다 |
| **고사실을 넘는 공유** (`--cross-room`) | 휴대폰으로 답 돌리기 | MinHash LSH로 오답 집합이 많이 겹치는 쌍만 후보로 뽑아 정밀 검정합니다. 판정은 **전체 쌍 수**(10만 명이면 50억 쌍)로 보정합니다 | 전국 규모 O(n²) 없이 |
| **학교 보정** (`school` 열) | 같이 배워서 생기는 공통 오답을 베끼기로 오해하는 문제 | 학교·학원별 선택 성향을 축소 추정해 확률을 기울입니다 | 아래 견고성 실험 참고 |
| **공모 집단** | 여러 명이 얽힌 공유 | 판정된 쌍을 연결해 집단으로 묶습니다 | 군집 분석 |
| **고사실 분석** | 감독관 묵인 같은 고사실 단위 부정 | 고사실 안 유사 쌍 개수가 기대값보다 많은지 이항 검정을 합니다 | 시험장 내 군집 |
| **AI 우도비** (새 방법) | AI 사용 | 조사자가 AI를 여러 번 돌려 얻은 문항별 AI 선택 분포로 **"f 비율을 AI 답으로 채웠다" 대 "정직"** 우도비를 계산합니다. AI가 맞힌 문항과 틀린 문항 정보를 모두 씁니다 | 없음 |
| **AI 오답 일치** (새 방법) | AI 사용 | AI가 틀린 문항에서 같은 오답을 고른 수입니다. 설명하기 쉬운 보조 근거입니다 | 없음 |
| **이상응답** | 응답 패턴이 통째로 드문 경우 | 같은 점수대 기준 패턴의 놀라움(-log 확률) 합의 정확 검정입니다. 문항반응이론 가정 없이 선택지 정보까지 씁니다 | 개인 적합도(aberrance) |
| **사전 유출** | 문제 유출 | 유출 의심 문항 정답 수를 **유출되지 않은 문항 점수**로 나눈 점수대와 비교합니다 | 사전 지식(pre-knowledge) |
| **응답시간** | 시간 패턴이 들쭉날쭉하거나 지나치게 일정함(받아 적기) | 로그정규 응답시간 모형(van der Linden 2006)으로 ① 잔차 변동 ② **시간-문항 연동 기울기**를 계산하고, 실제 응시자 분포 기준(경험적 귀무분포)으로 극단값을 봅니다 | 응답시간(latency) |
| **실력 대비 속도** (순위 점수) | 문제를 미리 알아 전체적으로 빨리 풂 | 점수가 같은 사람들보다 얼마나 빠른지의 강건 z입니다. 실데이터에서 가장 강한 신호지만 p값이 맞지 않아 판정에는 쓰지 않습니다 | |
| **성적 급상승** | 평소 실력과 동떨어진 점수 | 이전 성적에 회귀한 잔차를 봅니다 | 성적변화(gains) |
| 거트만 G\* | 참고용 | 비모수 지표라 판정에 쓰지 않습니다 | |

**판정 기준:** 방법마다 본페로니 보정을 적용합니다(기본 α = 0.05 ÷ 그 방법의 검정 수). **시험 전체에서 정직한 사람이 한 명이라도 잘못 걸릴 확률**이 방법당 5% 이하입니다.

**2단계 추정:** 부정행위자가 많으면 그들의 선택이 "흔한 선택"처럼 보여서 스스로를 가립니다. 그래서 1차에서 느슨한 기준(p < 0.001)에 걸린 사람을 빼고 선택 확률을 다시 추정합니다.


## AI 응답 수집 (`collect-ai`)

시험 직후 최대한 빨리, 여러 모델을 여러 번 돌려 `ai.csv`에 모으세요. 같은 파일에 이어 쓰므로 모델별로 반복 실행하면 됩니다.

```bash
# Claude (공식 SDK, ANTHROPIC_API_KEY 필요)
pip install anthropic
python -m exam_forensics collect-ai questions.json --provider anthropic --model claude-opus-5-5 --runs 5 --out ai.csv

# OpenAI 호환 API (OpenAI, Gemini, DeepSeek 등): 키는 환경변수 이름으로만 전달합니다
python -m exam_forensics collect-ai questions.json --provider openai --base-url https://api.openai.com/v1 \
    --api-key-env OPENAI_API_KEY --model <모델이름> --out ai.csv

# 로컬 AI (Ollama): 인터넷 없이 수집
python -m exam_forensics collect-ai questions.json --provider openai --base-url http://localhost:11434/v1 --model <모델이름> --out ai.csv
```

`questions.json` 형식 (`id`는 응답 CSV의 문항 열 이름과 같아야 합니다):

```json
[{"id": "q1", "question": "다음 중 ...", "choices": ["보기1", "보기2", "보기3", "보기4", "보기5"]}]
```

- Anthropic 공급자는 안전 분류기가 응답을 거절할 때 다른 모델로 넘기는 서버 측 대체(`fallbacks`)를 켜 둡니다. 그래도 거절되면 해당 문항은 무응답(0)으로 기록됩니다.
- `ai.csv`에는 모델 이름, 회차, 수집 시각이 기록됩니다. AI 모델은 계속 업데이트되므로, 수집 시각은 증거 신뢰성에 중요합니다.
- 그림이나 도표가 있는 문항은 아직 지원하지 않습니다(텍스트 문항만).

## 입력 형식 (UTF-8 CSV)

`responses.csv`: 한 행이 수험생 한 명입니다. `id`, `group`, `prior` 외의 열은 문항으로 취급합니다.

```
id,group,prior,q1,q2,q3,...
s0,room01,72.5,3,1,5,...
```

- 응답: `1`~`K` 선택지 번호, 빈칸이나 `0`은 무응답
- `group` (선택): 고사실. 있으면 같은 고사실 안의 쌍만 비교하고 고사실 분석도 합니다
- `school` (선택): 출신 학교·학원. 있으면 공통 오답 성향을 보정합니다. 학교 효과가 없을 때는 부분 베끼기 탐지력이 10~12%p 떨어지므로, 학교가 고사실과 겹치거나 경고가 뜰 때 쓰세요
- `prior` (선택): 이전 성적

`key.csv`: 문항 열과 같은 헤더, 정답 한 행
`ai.csv` (선택): `model`, `run`, `collected_at`, 문항 열. 같은 모델의 여러 행은 하나의 분포로 합칩니다
`times.csv` (선택): `id`와 문항 열, 값은 초 단위 응답시간 (컴퓨터 시험에서 수집)

## 실제 시험 데이터 검증

**데이터:** Cizek & Wollack (2017) *Handbook of Quantitative Methods for Detecting Cheating on Tests*의 실제 자격시험 데이터 ([Zopluoglu 공개본](https://cengiz.me/posts/xgboost/)). 4지선다, 시험지 2종(각 170문항, 약 1,600명), 문항별 응답시간이 있습니다. 시험 업체가 **사전유출 의심자로 표시한 94명**(약 2.9%)이 라벨입니다. 데이터는 저장소에 포함하지 않으며, 쓸 때 핸드북을 출처로 밝혀 주세요.

```bash
python benchmarks/cizek_wollack.py <train.csv, test.csv 폴더>   # 업체 라벨과 비교
python benchmarks/plant_real.py <같은 폴더>                     # 실제 응답 위 심기 실험
```

**업체 라벨 대비 (라벨 없이 쓰는 비지도 방식, 두 시험지 3,211명):**

| 지표 | AUC | 오탐 1% / 5%일 때 탐지 |
|---|---|---|
| 답안 공유 | 0.63 | 24% / 29% |
| 이상응답 | 0.61 | 10% / 13% |
| 응답시간 | 0.61 | 1% / 12% |
| 실력 대비 속도 (순위 점수) | 0.77 | 46% / 47% |
| **순위 최댓값 결합** | **0.92** | 27% / **78%** |

참고: 같은 데이터에 라벨로 학습한 XGBoost(지도학습)가 AUC 0.93이라는 보고가 있습니다(검증하지 않은 수치). 이 도구는 라벨 없이 0.92입니다.

**본페로니 판정 22명:** 업체 표시자 12명, 비표시자 10명입니다. 답안 공유 판정 13쌍 중 7쌍은 둘 다 표시자, 4쌍은 한 명만 표시자, 2쌍은 둘 다 비표시자였습니다. **한 명만 표시된 쌍의 짝은 표시자와 같은 오답을 기대값의 약 2배 공유했으므로, 업체가 놓친 공모 상대일 수 있습니다.** 다만 확인할 방법은 없습니다.

**실제 응답 위 심기 실험** (업체 비표시자만 사용, 1%씩 심음): 베끼기 70%·100%, AI 80%·100% 모두 **90/90명(100%) 탐지**. 170문항이라 정보량이 많기 때문입니다. 부정을 심지 않은 상태에서 비표시자 중 판정은 시험지당 약 2명이었습니다.

**실데이터에서 발견하고 고친 문제:**

- **응답시간 검정의 오탐 폭발.** 이론적 카이제곱을 쓰자 정상 응시자의 31%가 p<0.01에 걸렸고, 1,607명 중 160명이 판정됐습니다. 사람마다 시간 변동 폭이 원래 다르기 때문입니다. 응시자 분포의 중앙값과 MAD로 기준을 잡는 **경험적 귀무분포**로 바꾸자 p<0.01 비율이 1.1~1.6%가 됐고, 판정은 1명으로 줄었습니다.
- **가장 강한 실제 신호는 "실력 대비 속도"였습니다.** 업체 표시자는 점수는 평범한데 전체적으로 표준편차의 약 1.7배만큼 빨랐습니다. 하지만 빠른 쪽 꼬리가 두꺼워 p값이 맞지 않아서(정상 응시자의 7~8%가 p<0.01), **판정에는 넣지 않고 순위 점수로만** 냅니다.
- **유출 문항 자동 탐색은 실패했습니다.** "빠르게 맞힌" 패턴의 문항 간 상관으로 유출 문항을 찾는 교차 적합 방식을 시도했지만 AUC가 0.38~0.48로 무작위보다 못해서 넣지 않았습니다.

**이 검증의 한계:**
- 라벨은 확정된 정답이 아니라 업체의 의심 목록입니다. 업체가 속도를 보고 표시했다면 속도 지표의 성적은 부풀려졌을 수 있습니다.
- 정답 키가 데이터에 없어서 응답에서 추정했습니다.
- 라벨이 사전유출뿐이라 AI 탐지는 실제 라벨로 검증되지 않았습니다(심기 실험만 했습니다).
- 결합 방식(순위 최댓값)은 두 방식을 비교한 뒤 골랐으므로 약간의 선택 편향이 있습니다.
- 데이터셋이 하나뿐입니다.

## 가상 데이터 검증

`simulate.py`는 3모수 문항반응이론(3PL), 문항별 오답 매력도, 로그정규 응답시간으로 수험생 1만 명 × 45문항(5지선다)을 만들고, 고사실(28명)마다 섞이도록 부정행위자를 유형별 1%씩 심습니다. 정답을 알기 때문에 탐지율과 오탐을 측정할 수 있습니다.

**오탐:** 부정행위자가 없는 시험 10회(정직한 수험생 10만 명)에서 전체 방법 합쳐 **1명**, 고사실 3,580곳 중 **0곳**이었습니다. 고사실 구분 없이 3,000명의 모든 쌍(450만 쌍)을 검정해도 0명이었습니다.

**탐지율 (seed 0~2 평균), v0.1(같은 오답 개수 검정만) 대비:**

| 조건 | 답안 공유 v0.1 → v0.2 | AI 사용 v0.1 → v0.2 | 정직한 수험생 오탐 |
|---|---|---|---|
| 50% 문항을 베낌 | 3% → **30%** | | 약 2.9만 명 중 1명 |
| 70% 문항을 베낌 | 30% → **65%** | | 1명 |
| 전부 베낌 | 69% → **90%** | | 1명 |
| AI를 50% 문항에 사용 | | 4% → **10%** | 1명 |

### 견고성: 모형이 틀릴 때

귀무 모형은 "같은 점수대면 누구나 같은 확률로 오답을 고른다"고 가정합니다. 실제로는 같이 배운 학생들이 같은 오답을 고릅니다. 학원 효과(학원별 문항 난이도 차이, 공통 오답 습관)를 넣은 가상 데이터로 정직한 수험생 3만 명(3회)의 오탐을 쟀습니다.

| 조건 | 보정 없음 | 학교 보정 (`school`) |
|---|---|---|
| 학원 30곳, 고사실과 무관하게 배정 (강한 효과) | 0명 | |
| 작은 학원 300곳, 고사실과 무관 (강한 효과) | 0명 | |
| 고사실 = 학교 (중간 효과) | 0명 | |
| **고사실 = 학교 (강한 효과)** | **240명 오탐, 고사실 169곳 오판** + 경고 | **0명, 0곳** |

학교가 고사실과 겹치고 효과가 강할 때만 무너졌고, 이때는 자동 경고가 뜨며 학교 보정으로 해결됩니다. 보정 강도는 0.5/2/5/15를 실험해 오탐 0을 지키는 값(2)으로 정했습니다.

**규모:** 고사실을 넘는 공유(`--cross-room`, 0.5%가 다른 고사실 사람의 답을 베낌)

| 인원 | 전부 베낌 탐지 | 70% 베낌 탐지 | 정직 오탐 | 검정한 쌍 | 시간 |
|---|---|---|---|---|---|
| 1만 명 | 90% | 44% | 0명 | 5천만 | 10초 |
| 10만 명 | 68% | 22% | 0명 | 50억 | 92초 |

인원이 늘면 보정할 쌍이 n²로 늘어 기준이 엄격해지고, LSH도 후보 수를 묶느라 재현율이 떨어집니다.

### 정직한 한계

- **가상 데이터는 현실이 아닙니다.** 실데이터 검증은 아직 데이터셋 하나뿐입니다. 실제로 응답시간 검정은 가상 데이터에서 멀쩡했는데 실데이터에서 오탐이 폭발했습니다. 실제 적용 전에 그 기관의 과거 시험 데이터로 오탐률을 꼭 확인하세요.
- **AI 시뮬레이션 가정:** AI는 문항마다 선호 답이 있고 실행마다 85% 확률로 같은 답을 낸다고 가정했습니다. 실제 AI의 일관성은 모델과 문항마다 다릅니다.
- **수험생이 쓴 AI와 조사자가 돌린 AI가 같다는 보장이 없습니다.** 앱과 API의 설정 차이, 모델 업데이트 때문에 답이 다를 수 있습니다. 여러 모델을 수집하면 도움이 되지만 검정 수가 늘어 기준이 엄격해집니다.
- **AI를 일부 문항에만 쓰면 잘 안 잡힙니다** (50% 사용 시 10%). 정보량의 한계입니다.
- **유출 문항이 적거나 원래 쉬우면 사전유출 검정의 힘이 약합니다.** 응답시간이 있으면 보완됩니다.
- **이전 성적 기준 점수대는 쓰면 안 됩니다.** 실험해 보니 잡음 큰 기준으로 점수대를 나누면 문항 간 독립 가정이 깨져 1만 명당 6명 오탐이 났습니다. 그래서 모든 검정은 총점(사전유출은 비유출 문항 점수) 기준 점수대를 씁니다.
- **고사실 분석**은 한 사람이 여러 쌍에 들어가 쌍끼리 독립이 아니라서 근사 검정입니다.
- **고사실 전체 부정과 학교 효과는 통계로 구분되지 않습니다.** 학교 보정을 켜면 고사실 전체가 짜고 하는 부정도 함께 약해집니다.

## Caveon과의 객관적 비교

Caveon의 실제 수식(M4 등)과 소프트웨어는 비공개라 같은 데이터로 맞대결할 수 없습니다. 아래는 공개 자료 기준 비교이며, **"Caveon보다 낫다"는 실제 데이터 비교 없이는 주장할 수 없습니다.**

| 항목 | Caveon (공개 자료 기준) | exam-forensics |
|---|---|---|
| 실제 시험 데이터 검증 | 20년 이상, 다수 기관 | 공개 데이터셋 1개 (업체 라벨 대비 AUC 0.92) |
| 법정·징계 절차 증언, 조사 지원 | 있음 | 없음 |
| 통계 종류 | 25개 이상 | 9개 계열 |
| 정답 변경(지운 흔적) 분석 | 있음 | 없음 |
| 컴퓨터 적응형 시험(CAT) | 지원 | 미지원 |
| AI 부정행위 전용 검정 | 공개 자료에서 확인 못 함 | **AI 우도비, AI 오답 일치, AI API 수집** |
| p값 계산 | 공개 안 됨 | **모든 검정 근사 없는 정확 분포** |
| 받아 적기 응답시간 패턴 | 응답시간 분석 있음 | **시간-문항 연동 기울기 검정** |
| 고사실을 넘는 전국 단위 탐색 | 시험장 간 비교 있음 | LSH, 10만 명 92초 |
| 데이터 반출 | 서비스 업체로 전달 | **기관 내부에서만 처리** |
| 코드 공개·재현성 | 비공개 | **전부 공개, 가상 실험 재현 가능** |
| 비용 | 유료 계약 | 무료 (MIT) |

정리하면, **AI 부정행위 대응, 투명성, 데이터 반출 없음**은 객관적으로 앞서 있다고 말할 수 있습니다. 반면 **실전 검증과 운영 경험**에서는 크게 뒤처집니다. 공개 데이터셋 하나로 첫 검증을 했지만, 여러 기관의 실제 데이터로 오랜 기간 검증해야 이 격차를 메울 수 있습니다.
