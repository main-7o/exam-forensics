# exam-forensics

시험 응답 데이터를 넣으면 답안을 돌려본 사람, AI로 문제를 푼 사람, 문제를 미리 알고 들어온 사람처럼 수상한 응시자를 통계로 찾아주는 도구예요.

만들게 된 계기는 2026년 가을에 연달아 터진 시험 AI 부정 사건들이었어요. 세무사 시험 수석 합격자가 AI 부정으로 조사를 받고, LEET 만점자에게 스마트안경 의혹이 붙고, 결국 작년 수능 시험지까지 보관하라는 지시가 내려왔죠. 그런데 정작 "그래서 누가 수상한지 데이터로 어떻게 찾느냐"는 질문에 답할 도구가 국내에는 마땅히 없더라고요. 해외에는 Caveon 같은 시험 보안 전문 업체가 있지만 비공개 유료 서비스라서, 그 업체들이 쓰는 분석 기법을 공개된 방법으로 직접 구현하고 AI 부정 탐지를 더해서 만들었어요.

모든 분석은 내 컴퓨터 안에서만 돌아가요. 분석 코드에는 인터넷에 접속하는 부분이 아예 없어서 수험생 데이터가 밖으로 나갈 일이 없고, 필요한 건 Python과 numpy뿐이에요. 1만 명이 45문항을 푼 시험이면 노트북에서 6초 정도면 끝나요.

한 가지 꼭 짚고 넘어갈 게 있어요. 이 도구가 내놓는 결과는 부정행위의 증거가 아니라 "이 사람부터 살펴보는 게 좋겠다"는 신호예요. 통계적으로 아무리 수상해도 우연일 가능성은 남아 있으니까, 최종 판단은 감독 기록이나 진술 같은 다른 근거와 함께 사람이 내려야 해요.

## 바로 써보기

```bash
pip install numpy
python -m exam_forensics demo
```

`demo`는 가짜 시험 데이터를 만들고 부정행위자를 일부러 섞어 넣은 다음, 도구가 그중 몇 명을 잡고 정직한 사람은 몇 명이나 잘못 잡는지 보여줘요. 실제 파일로 돌려보고 싶다면 예제 데이터를 먼저 만들어서 분석해 보면 돼요.

```bash
python -m exam_forensics simulate --out sample
python -m exam_forensics analyze sample/responses.csv --key sample/key.csv \
    --ai sample/ai.csv --times sample/times.csv --leaked q3,q7 --out report
```

분석이 끝나면 `report` 폴더에 결과가 생겨요. `examinees.csv`에는 수험생마다 어떤 검사에서 얼마나 수상하게 나왔는지가, `pairs.csv`에는 답이 이상할 만큼 비슷한 두 사람의 짝이, `rooms.csv`에는 고사실별 결과가 들어 있어요. 휴대폰으로 다른 고사실 사람과 답을 주고받은 경우까지 찾고 싶다면 `--cross-room`을 붙이면 돼요.

## 데이터는 이렇게 넣어요

가장 중요한 건 `responses.csv`예요. 한 줄에 수험생 한 명씩, 각 문항에 고른 선택지 번호를 적으면 되고 답을 안 쓴 문항은 비워두거나 0으로 두면 돼요.

```
id,group,prior,q1,q2,q3,...
s0,room01,72.5,3,1,5,...
```

`id`, `group`, `school`, `prior`를 빼고는 전부 문항으로 읽어요. `group`에 고사실을 적어주면 같은 고사실 안에서만 짝을 비교하고 고사실 단위로도 분석해요. `school`에는 출신 학교나 학원을, `prior`에는 모의고사 같은 이전 성적을 넣을 수 있는데, 둘 다 없어도 돌아가요.

그 밖에 정답을 담은 `key.csv`는 꼭 필요하고, AI 답안을 모은 `ai.csv`와 문항별 풀이 시간(초)을 담은 `times.csv`는 있으면 쓰는 선택 사항이에요. 풀이 시간은 컴퓨터로 보는 시험(CBT)에서만 나오는 데이터라 종이 시험이면 없어도 괜찮아요.

## 무엇을 어떻게 찾나요

기본 아이디어는 "비슷한 점수를 받은 사람들은 보통 이렇게 답한다"를 데이터에서 직접 배운 다음, 거기서 크게 벗어난 사람을 찾는 거예요. 예를 들어 비슷한 실력의 수험생 대부분이 3번이나 4번을 고르는 문항에서 두 사람이 나란히 아무도 안 고르는 1번을 골랐다면, 그런 일이 우연히 일어날 확률을 계산할 수 있겠죠. 이 도구는 그 확률을 근사 없이 정확하게 계산해요.

수천 명을 한꺼번에 검사하면 우연히 극단적인 값이 나오는 사람이 생기기 마련이에요. 그래서 검사 횟수만큼 기준을 엄격하게 올려서(본페로니 보정), 시험 전체를 통틀어 정직한 사람이 한 명이라도 잘못 걸릴 확률을 검사 방법마다 5% 아래로 묶어 두었어요.

**답을 돌려본 사람.** 먼저 모든 두 사람 짝에 대해 같은 오답이 몇 개나 겹치는지 봐요. 여기서 걸린 짝은 한 번 더 정밀하게 따지는데, 어려운 문항의 정답이나 거의 아무도 안 고르는 오답이 겹칠수록 더 무겁게 쳐요. 의심 짝들은 서로 이어서 몇 명이 함께 얽힌 집단인지도 보여주고, 한 고사실에 비슷한 짝이 유독 많으면 고사실 전체를 따로 표시해요.

전국 단위로 모든 짝을 비교하면 10만 명만 돼도 50억 쌍이라 현실적으로 계산이 안 돼요. 그래서 `--cross-room`을 켜면 오답 패턴이 많이 겹치는 짝만 빠르게 골라내는 해싱 기법(MinHash LSH)으로 후보를 먼저 추린 뒤 검사해요.

**AI로 푼 사람.** 시험이 끝나면 여러 AI 모델에게 같은 문제를 몇 번씩 풀게 해서 AI가 어떻게 답하는지 모아 둬요. 그러고 나서 수험생의 답이 사람들의 일반적인 답보다 AI 쪽으로 얼마나 기울어 있는지를 봐요. 특히 AI는 틀릴 때도 특유의 오답을 고르는데, 수험생이 그 오답을 그대로 따라 골랐다면 설명하기 쉬운 강한 근거가 돼요.

**문제를 미리 안 사람.** 유출이 의심되는 문항을 알고 있다면, 그 문항들만 유독 잘 맞혔는지 확인할 수 있어요. 이때 비교 기준은 유출되지 않은 문항의 점수로 잡아요. 총점을 기준으로 삼으면 유출 덕분에 올라간 점수가 오히려 신호를 가려버리거든요.

**풀이 시간이 이상한 사람.** 보통 사람은 어려운 문항에서 오래 걸리고 쉬운 문항은 빨리 넘어가요. 그런데 누군가 불러주는 답을 받아 적고 있다면 문항 난이도와 상관없이 시간이 거의 일정하게 나오겠죠. 반대로 시간이 지나치게 들쭉날쭉한 경우도 함께 잡아요. 여기에 더해 비슷한 점수의 사람들보다 유난히 빨리 푼 사람도 따로 점수로 보여주는데, 이건 실제 데이터에서 가장 잘 맞았던 지표예요. 다만 확률 계산이 정확하지 않아서 판정에는 넣지 않고 참고용 순위로만 쓰고 있어요.

그 밖에 응답 패턴 전체가 같은 점수대에서 보기 드문 사람, 이전 성적에 비해 점수가 갑자기 뛴 사람도 찾아요.

**같은 학교 학생이 모여 앉는 경우.** 같은 학교에서 같은 선생님께 배운 학생들은 오답까지 비슷하게 고르는 경향이 있어요. 이 학생들이 한 고사실에 모여 앉으면 정직하게 풀었는데도 답을 베낀 것처럼 보일 수 있죠. 판정된 고사실이 전체의 5%를 넘으면 도구가 이런 가능성을 경고해 주는데, 그때 `school` 열을 넣고 다시 돌리면 학교별 경향을 감안해서 다시 판단해요. 다만 학교 효과가 없는 시험에서 이걸 켜면 일부만 베낀 사람을 놓치는 비율이 10%p쯤 늘어나니까, 경고가 떴을 때만 켜는 걸 권해요.

## AI 답안 모으기

`collect-ai` 명령은 AI에게 시험 문제만 보내고, 수험생 데이터는 전혀 건드리지 않아요. Ollama처럼 내 컴퓨터에서 도는 모델을 쓰면 이 단계까지 인터넷 없이 할 수 있어요.

```bash
# Anthropic API (ANTHROPIC_API_KEY 필요)
pip install anthropic
python -m exam_forensics collect-ai questions.json --provider anthropic --model claude-opus-5-5 --runs 5 --out ai.csv

# OpenAI 호환 API (OpenAI, Gemini, DeepSeek 등). API 키는 환경변수 이름으로 넘겨요
python -m exam_forensics collect-ai questions.json --provider openai --base-url https://api.openai.com/v1 \
    --api-key-env OPENAI_API_KEY --model <모델> --out ai.csv

# 내 컴퓨터의 모델 (Ollama)
python -m exam_forensics collect-ai questions.json --provider openai --base-url http://localhost:11434/v1 --model <모델> --out ai.csv
```

문제 파일은 아래처럼 만들면 되고, `id`는 응답 CSV의 문항 이름과 같아야 해요.

```json
[{"id": "q1", "question": "다음 중 ...", "choices": ["보기1", "보기2", "보기3", "보기4", "보기5"]}]
```

모델을 바꿔가며 여러 번 돌리면 같은 `ai.csv`에 계속 쌓여요. AI 모델은 수시로 업데이트되기 때문에 시험이 끝나면 되도록 빨리 모아두는 게 좋고, 언제 모았는지는 파일에 자동으로 남아요. 아직은 그림이나 도표가 들어간 문항은 처리하지 못해요.

## 실제 시험 데이터로 확인해 봤어요

가짜 데이터에서 잘 되는 것만으로는 믿을 수 없어서, 시험 부정 탐지 분야의 교과서로 꼽히는 Cizek & Wollack(2017) *Handbook of Quantitative Methods for Detecting Cheating on Tests*에 실린 실제 자격시험 데이터로 검증해 봤어요([공개본](https://cengiz.me/posts/xgboost/)). 약 3,200명이 170문항짜리 시험지 두 종 중 하나를 풀었고, 문항별 풀이 시간까지 들어 있어요. 시험 업체가 "문제를 미리 본 것 같다"고 표시한 94명이 있어서 이 표시와 얼마나 맞는지 비교했어요. 데이터 자체는 저장소에 넣지 않았으니 직접 받아서 돌려보면 되고, 쓸 때는 핸드북을 출처로 밝혀야 해요.

```bash
python benchmarks/cizek_wollack.py <train.csv, test.csv가 있는 폴더>
python benchmarks/plant_real.py <같은 폴더>
```

정답 라벨을 전혀 보여주지 않고 돌렸는데도, 여러 지표를 합친 점수로 업체 표시자를 가려내는 정확도(AUC)가 0.92가 나왔어요. 참고로 같은 데이터에서 라벨을 보고 학습한 머신러닝 모델이 0.93을 냈다는 보고가 있으니 꽤 근접한 셈이에요. 지표별로 보면 이래요.

| 지표 | AUC | 정직한 사람을 1% / 5% 잘못 잡을 때 찾아낸 비율 |
|---|---|---|
| 답안 공유 | 0.63 | 24% / 29% |
| 이상한 응답 패턴 | 0.61 | 10% / 13% |
| 풀이 시간 | 0.61 | 1% / 12% |
| 실력 대비 속도 | 0.77 | 46% / 47% |
| 여러 지표 결합 | 0.92 | 27% / 78% |

엄격한 기준으로 최종 판정된 사람은 22명이었고, 그중 12명이 업체 표시자였어요. 흥미로운 건 나머지인데, 답안 공유로 걸린 13쌍 가운데 4쌍은 한 명만 업체 표시자였어요. 표시되지 않은 쪽도 표시자와 같은 오답을 우연의 두 배쯤 공유하고 있어서, 업체가 놓친 공범일 가능성이 있어요. 물론 이걸 확인할 방법은 없어요.

실제 데이터에 가짜 부정행위를 일부러 섞어 넣는 실험도 했는데, 베끼기와 AI 부정 모두 90명 중 90명을 찾아냈어요. 170문항이나 되다 보니 정보가 충분했던 덕이에요.

사실 이 검증에서 제일 값졌던 건 가짜 데이터로는 몰랐던 문제를 찾은 거예요. 처음에는 풀이 시간 검사가 이론적인 분포를 기준으로 삼았는데, 실제로 돌려보니 1,607명 중 160명을 수상하다고 잡아버렸어요. 사람마다 시간이 들쭉날쭉한 정도가 원래 제각각인데 모형이 그걸 몰랐던 거죠. 그래서 실제 응시자들의 분포를 기준으로 삼도록 바꿨고, 그 뒤로는 1명으로 줄었어요. 업체 표시자들이 점수는 평범한데 유독 빨리 풀었다는 것도 이때 발견했어요. 반대로 유출 문항을 목록 없이 자동으로 찾아내는 방법도 시도해 봤는데, 결과가 찍는 것보다도 못해서 깔끔하게 포기했어요.

이 검증에도 한계는 있어요. 업체 표시는 확정된 사실이 아니라 의심 목록일 뿐이고, 업체가 풀이 속도를 보고 표시했다면 속도 지표의 성적은 부풀려졌을 수 있어요. 정답 키가 데이터에 없어서 응답 패턴으로 추정해야 했고, 라벨이 문제 유출 하나뿐이라 AI 부정은 실제 라벨로 확인하지 못했어요. 무엇보다 아직 데이터셋이 하나뿐이에요.

## 가짜 데이터로 해본 실험

`simulate.py`는 실제 시험과 비슷한 가짜 데이터를 만들고 그 안에 부정행위자를 심어 둬요. 누가 부정행위자인지 알고 있으니 도구가 얼마나 잡고 얼마나 헛짚는지 정확히 셀 수 있죠.

부정행위자가 한 명도 없는 시험을 10번, 총 10만 명분 돌렸을 때 잘못 잡힌 사람은 1명이었어요. 부정행위자를 섞었을 때는 문항을 전부 베낀 사람의 90%, 70%만 베낀 사람의 65%, 절반만 베낀 사람의 30%를 찾았어요. AI를 모든 문항에 쓴 사람은 90%, 80% 문항에 쓴 사람은 61%를 찾았지만, 절반만 쓴 사람은 10%밖에 못 잡았어요. 같은 오답 개수만 세는 단순한 방식과 비교하면 절반 베끼기는 3%에서 30%로, AI 80% 사용은 26%에서 61%로 좋아졌어요.

같은 학교 학생이 모여 앉는 상황도 일부러 만들어 봤어요. 학원이 고사실과 상관없이 흩어져 있을 때는 영향이 강해도 문제가 없었는데, 학교와 고사실이 겹치고 영향이 강하면 정직한 3만 명 중 240명이 베낀 것으로 잘못 잡혔어요. 이때는 경고가 떴고, 학교 정보를 넣어 다시 돌리니 0명이 됐어요.

다른 고사실 사람의 답을 베끼는 경우는 1만 명 시험에서 전부 베낀 사람의 90%를 10초 만에, 10만 명 시험에서는 68%를 1분 30초쯤에 찾았고, 둘 다 정직한 사람은 한 명도 잘못 잡지 않았어요.

## 아직 부족한 점

실제 데이터 검증이 하나뿐이라는 게 가장 커요. 풀이 시간 검사가 가짜 데이터에선 멀쩡하다가 실제 데이터에서 무너졌던 것처럼, 실제 시험마다 예상 못 한 문제가 숨어 있을 수 있어요. 그러니 실제로 쓰기 전에는 그 기관의 지난 시험 데이터로 먼저 돌려보고 오탐이 얼마나 나오는지부터 확인하는 걸 권해요.

AI 쪽은 가정이 많아요. 가짜 데이터에서는 AI가 같은 문제에 85% 확률로 같은 답을 낸다고 놓았는데 실제 모델은 다 달라요. 수험생이 쓴 AI와 나중에 조사하면서 돌린 AI가 같다는 보장도 없고요. AI를 일부 문항에만 쓴 경우는 지금도 잘 못 잡아요.

그 밖에 고사실 전체가 짜고 친 부정과 같은 학교 효과는 통계만으로는 구분이 안 되고, 정답을 지웠다 고친 흔적 분석이나 컴퓨터 적응형 시험(CAT)은 아직 지원하지 않아요. 이전 성적을 기준으로 비교하는 방법도 시도해 봤는데, 1만 명당 6명꼴로 오탐이 나와서 넣지 않았어요.

## 상용 서비스와 비교하면

Caveon 같은 상용 서비스는 수식도 소프트웨어도 공개하지 않아서 같은 데이터로 맞붙여 볼 수는 없어요. 공개된 자료로만 비교하면, 상용 서비스는 20년 넘게 여러 기관의 실제 시험으로 검증돼 왔고 조사 지원이나 법정 증언까지 해주는 반면, 이 도구는 아직 공개 데이터셋 하나로 확인한 수준이에요. 대신 AI 부정을 따로 겨냥한 분석이 있고, 계산 방식이 전부 공개돼 있고, 수험생 데이터를 외부 업체에 넘길 필요가 없고, 무료라는 점은 분명한 장점이에요. 결국 남은 격차는 코드가 아니라 실제 데이터로 메워야 하는 부분이에요.
